# Cookie and browser-storage notice

Owner requested a formal researched notice on October 20, 2026. Returning-visit display preferences were revised October 21, 2026. This records current implementation and disclosure; it does not claim that every legal launch requirement is completed.

## Inventory and implementation

- `src/account.tsx` keeps Supabase PKCE authentication in `window.sessionStorage`, without a custom localStorage fallback. The sign-in session contains authentication/account information and the sign-in verifier completes the provider return. Neither stores chats. Provider-domain storage is separate. Browser restoration may retain a tab's session, so shared-device users should sign out.
- Application source has no analytics/advertising SDK, pixel, fingerprinting implementation, `document.cookie` writer or application `Set-Cookie` response. Vercel's project dashboard showed Analytics and Speed Insights not enabled during the October 20 release verification. This does not guarantee that hosting/security providers never set their own functional cookies.
- `src/storage-notice.ts` uses exactly one versioned localStorage key, `offscript.storage-notice.2026-10-21`. Only an explicit **Got it** action writes its timestamp value. It contains no user/account identifier, token, chat or tracking ID and is not sent as an analytics event. Merely visiting, opening details or signing in does not write this preference.
- That browser preference suppresses this version of the notice for **180 days from the explicit click**, including later tabs and sign-ins on the same origin/browser. Reads do not refresh its timestamp. Future timestamps, expired values and malformed/legacy values do not suppress the notice. Expired entries are ignored; localStorage does not automatically erase them, and they may remain until replaced or site data is cleared. Changing the key version can show the notice again.
- No legacy tab dismissal is silently upgraded to a durable preference. The earlier session-storage key is neither enumerated nor deleted by this change. The helpers never enumerate or clear origin storage, access another key, overwrite authentication entries, or write chat content. Blocked/unavailable localStorage degrades to dismissal in the current page's React state.
- The **informational welcome** uses `user_metadata.offscript_welcome` in the authenticated user's Supabase account: `{version:'2026-10-21',forUser:originalAccountId}`. Only explicit welcome dismissal attempts to save this display preference via Supabase’s authenticated `PUT /auth/v1/user` endpoint. The request pins the captured session’s access token, uses only the configured HTTPS Supabase origin and publishable key, rejects redirects, and verifies the returned account. Switching the SDK session cannot redirect this write to another account. Before showing an unseen welcome from potentially stale session data, a credential-pinned account read confirms that the server still has no current marker; failed reads do not force this optional welcome. Late decisions for an account that has signed out or changed are ignored. The account/version guard also prevents another account’s marker from hiding its own notice. This is editable UI metadata, never authorization or trusted legal consent. It can be reflected in the tab's Supabase session and survive sign-out or browser-data deletion because its authoritative copy is account-linked; it works across devices for that account. It stores display state plus its account association, not chats or legal acceptance; save failure may cause a future repeat. This preference must never grant access, accept Terms, acknowledge a Privacy Policy, enable marketing or authorize payment. The cookie preference does not read or write account metadata.
- The storage notice is an in-flow, nonmodal region. Its button explains that dismissal is remembered on this browser for 180 days when storage is available. It does not cover the composer, stop chat or claim continued browsing grants consent. The Cookies footer control reopens details at any time. `/cookies.html` is generated from the same content and works without JavaScript or sign-in.
- There are no fake optional-cookie toggles or Accept all button because optional tracking is not enabled. Got it dismisses this informational notice; it is not tracking consent, Terms acceptance, a Privacy Policy acknowledgement, a marketing subscription or payment authorization. Authentication remains tab-scoped and conversations/drafts remain in page memory.
- The notice can appear again after expiry, a notice-version change, blocked/cleared site data, private browsing or use of another browser/device. This is a browser preference, not a claim to recognize returning accounts everywhere. Clearing browser data does not delete the account's separate welcome-display preference.

## Primary guidance checked October 21

- [Latvia DVI: cookie and privacy-policy guidance index](https://www.dvi.gov.lv/lv/sikdatnes-un-privatuma-politika), published January 7, 2025, currently lists cookie guidance and sample notices updated February 11, 2026. Use the current linked materials instead of assuming the index's publication date is the document version.
- [DVI: common cookie-banner mistakes](https://www.dvi.gov.lv/lv/jaunums/dviskaidro-kadas-kludas-visbiezak-tiek-pielautas-sikdatnu-baneros) supports a short explanatory acknowledgement when only functional storage is involved. It requires clear information and genuine choices for optional processing. This does not automatically classify every convenient display preference as exempt; purposes, necessity and the user's explicit request need to be considered.
- [DVI: easy withdrawal of cookie consent, November 4, 2025](https://www.dvi.gov.lv/lv/jaunums/dviskaidro-ka-nodrosinat-lietotajiem-iespeju-viegli-atsaukt-piekrisanu-sikdatnem) explains that optional analytics/marketing consent needs an equally accessible **site-provided** withdrawal control. Telling users to clear browser storage alone is insufficient for that future use. No optional tracking consent is collected here.
- [EU Your Europe: online privacy](https://europa.eu/youreurope/business/growing/digitalising/online-privacy/index_en.htm) distinguishes requested-service authentication/communication storage from purposes requiring prior specific consent. A dismissal preference does not authorize unrelated processing.
- [MDN: localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) explains cross-session persistence, private-browsing limitations and storage-denied exceptions. The 180-day limit is enforced by this application; it is a product retention choice, not a blanket statutory period or a built-in localStorage expiry.
- [ICO: storage and access technologies](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/what-are-storage-and-access-technologies/) covers browser storage as well as cookies. This is UK guidance for technical context, not a substitute for EU/national review.

Before any future optional tracking: inventory each purpose/vendor/lifetime, review applicable rules, block processing until the required choice, provide equally accessible rejection and site-provided withdrawal, and test network/storage behavior. Do not silently turn the notice preference or welcome display state into marketing consent. No optional tracking is activated by this release.
