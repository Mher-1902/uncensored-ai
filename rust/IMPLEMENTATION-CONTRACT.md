# Internal migration contract

This is a parallel, private candidate. Do not route production traffic to it yet.
Keep the exact GGUF/model/template, public protocol5, no saved chats, authentication boundary and resource/thermal limits. All builds/tests are on Samsung in bounded rootless Docker; never use Mac model compute or host Rust installs. Do not read credentials or customer prompt logs.

Module ownership: gateway/request/registry belong to gateway implementer; engine/stream belong to engine implementer; supervisor belongs to supervisor implementer; manifests/config/tokenizer/main/Docker/native hook/harness belong to root.

Shared interfaces:
- request: `Message { role:String, content:String }`; `Mode { Fast, Deep }` lowercase serde; `ChatInput { messages:Vec<Message>, max_tokens:usize, mode:Mode, continuation:bool }`; `validate_request(serde_json::Value, allow_bounded_tokens:bool) -> Result<ChatInput, BackendError>`.
- engine: `Prepared { input:ChatInput, prompt:String, input_tokens:Vec<u32>, output_budget:usize, reasoning_budget:usize }`; `ModelEvent::{Data(serde_json::Value), Done}`; `EngineStream=Pin<Box<dyn Stream<Item=Result<ModelEvent,BackendError>>+Send>>`; async-trait `Engine:Send+Sync { ready()->bool; dispose()->bool; prepare(&ChatInput,&CancellationToken)->Result<Prepared,...>; generate(Prepared,CancellationToken)->Result<EngineStream,...> }`.
- engine: `LlamaEngine::new(origin:&str, tokenizer:Arc<dyn Tokenizer>)->Result<Self,BackendError>`; tokenization is through `Tokenizer` trait below; readiness, preparation and dispatch require both native `/props` capabilities `offscript_input_tokens_version:1` and `offscript_erase_state_version:1`. Keep existing OpenAI chat SSE/reasoning parser, context/budget/continuation behavior. Extra native fields are `offscript_prompt_tokens` and `offscript_rendered_prompt`. Explicit slot erasure must drop the previous native task/sampler and prompt/hybrid-checkpoint references, then return `offscript_erase_state_version:1`, `id_slot:0`, and an unsigned `n_erased` no greater than4096; a generic2xx is insufficient. Rust bounds each proof body to16KiB and each of3attempts to5seconds. Missing/invalid proof prevents completion and quarantines gateway admission under the existing public protocol5. Never call C++ `/tokenize` in candidate.
- tokenizer: async-trait `Tokenizer:Send+Sync { ready()->bool; encode(&str, &CancellationToken)->Result<Vec<u32>,BackendError> }`. Root implements local Rust tokenizer. It loads/validates artifact once, disables BPE cache, limits encode concurrency, uses cancellation-aware bounded work, no prompt logs.
- gateway: `router(config:GatewayConfig, engine:Arc<dyn Engine>)->axum::Router`; all current private API routes including prepare/cancel, required protocol5 proofs. Public static content stays Vercel; unknown non-API routes can404. Caller gateway main supplies config access_token/origins. Native HTTP targets only loopback. Keep service JWTs at Vercel; only service credential reaches Rust gateway.
- supervisor: `pub async fn run(root:&std::path::Path)->Result<(),BackendError>`; reads same self-host/model.json, starts same native child args, integrity checks/readiness/private tmpfs, requires sensors, thermal stop85C (experiment harness75C), SIGTERM+bounded kill, no auto restart. Root provides subcommand wiring.

Tests must verify behavior, cleanup/isolation/races, meaningful failures; synthetic content only. Do not create fake benchmark speedups or silently fall back to old tokenization.
