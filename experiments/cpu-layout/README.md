# Private CPU weight-layout experiment

This experiment changes the existing Q4_K matrices to Q4_0 using BF16 weights from the same pinned HauhauCS Qwen3.5 2B checkpoint. Q4_0 has a simpler CPU decoding path. It is a hypothesis about this older AVX-only CPU, not a promised speed improvement.

The converter uses the pinned llama.cpp quantizer to generate the 152 replacement matrices from BF16, then patches their type descriptors and equally sized payloads in a verified copy of the serving GGUF. It copies the other 168 learned tensors without changing their bytes and independently verifies their readback. All metadata except the general file-type label remains identical, including every tokenizer field. No double quantization, stock checkpoint substitution, layer pruning, token truncation or public model change is involved.

The private Samsung artifact was produced at a peak of 59°C, with 0.25 CPU, 1 GiB RAM, zero swap and no external network. Its size remains 1,270,808,032 bytes. Conversion success does not establish model loading, speed, quality, sustained thermal behavior, cancellation or request isolation. The fixed general-answer/coding comparison completed at a peak of 69°C. The candidate decoded at about 3.53 and 3.72 tokens/second versus 3.83 and 4.06 for the original, and first text was slower in both samples. It remains rejected for latency and undeployed. Outputs differed, so whole-answer timing is not a controlled equal-length comparison. This small check does not establish quality or capacity. A fixed baseline seasons sample gave an incorrect causal explanation; answer quality remains an independent product gap.

`convert.py` is not imported by the application. It requires an explicit private fixture marker, Linux, a read-only container root, loopback-only networking and bounded CPU/RAM. The added entry guard passed separately in a 128 MiB/0.1 CPU offline Samsung container; the conversion entry rejected execution without its marker before opening model inputs. Syntax checks passed for all helpers. An external supervisor must enforce the 75°C guard, power/free-memory checks, public-work priority, scratch size and wall deadlines. Inputs and quantizer libraries must be read-only; credentials, user chat data, home directories and sockets must not be mounted. Only a new private output directory and RAM temporary directory may be writable.

Preserve production until a candidate passes measured general/coding quality and latency, full-budget temperatures/deadlines, Stop, disposal and fresh-request isolation. The current 512-token allowance stays unchanged; the rejected 768-token candidate remains inactive.

The fixed paths and quantizer hash describe the tested Samsung fixture. They are not a portable installer or automatic download/activation mechanism. Model files and binaries are excluded from Git.
